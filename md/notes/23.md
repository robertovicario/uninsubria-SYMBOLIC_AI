# Adversarial Search and Game Playing

## Adversarial Search

An adversarial search problem involves agents with conflicting objectives. The basic model is a two-player, zero-sum game with deterministic actions and perfect information.

***Assumptions:***

- **MAX** wants to maximize the final score.
- **MIN** wants to minimize the same score.
- The game ends after finitely many moves.

A game is defined by:

- $s_0$: the initial state.
- $\mathrm{TO\text{-}MOVE}(s)$: the player whose turn it is.
- $A(s)$: the legal moves.
- $T(s,a)$: the state after move $a$.
- $\mathrm{IS\text{-}TERMINAL}(s)$: the terminal-state test.
- $\mathrm{UTILITY}(s)$: the final score from MAX's perspective.

### Minimax Search

The algorithm selects the move with the best guaranteed outcome, assuming the opponent also plays optimally. It uses recursive depth-first search, propagating maximum values at MAX-nodes and minimum values at MIN-nodes.

The minimax value is:

$$
\boxed{\mathrm{MINIMAX}(s)=
\begin{cases}
\mathrm{UTILITY}(s), & s\text{ is terminal},\\
\max\limits_{a\in A(s)}\mathrm{MINIMAX}(T(s,a)), & \mathrm{TO\text{-}MOVE}(s)=\mathrm{MAX},\\
\min\limits_{a\in A(s)}\mathrm{MINIMAX}(T(s,a)), & \mathrm{TO\text{-}MOVE}(s)=\mathrm{MIN}.
\end{cases}}
$$

\bigskip
> ***Pseudocode***

As in the slides, the recursive functions return `(value, move)`. Here the root player is MAX, and `game.utility` returns the score from MAX's perspective.

```py
def minimax(game, state):
    return max_value(game, state)[1]

def max_value(game, state):
    if game.is_terminal(state):
        return game.utility(state), None
    value, move = -float("inf"), None
    for action in game.actions(state):
        score, _ = min_value(game, game.result(state, action))
        if score > value:
            value, move = score, action
    return value, move

def min_value(game, state):
    if game.is_terminal(state):
        return game.utility(state), None
    value, move = float("inf"), None
    for action in game.actions(state):
        score, _ = max_value(game, game.result(state, action))
        if score < value:
            value, move = score, action
    return value, move
```

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Complete | Yes, for a finite game tree |
| Optimal | Yes, against an optimal opponent |
| Time | $O(b^m)$ |
| Space | $O(bm)$; $O(m)$ with successors generated one at a time |
| Advantages | finds the best guaranteed outcome |
| Disadvantages | explores an exponentially large game tree |

Here $b$ is the branching factor and $m$ is the maximum game-tree depth. In chess, typical estimates are $b\approx35$ and a game length of about $80$ moves, making exhaustive search impractical.

\bigskip
> ***Multiplayer Games***

With more than two players, use $\mathrm{UTILITY}(s,p)$ for each player $p$ and propagate vectors of scores. Each player chooses according to its own score; alliances may arise.

### Alpha-Beta Pruning

The algorithm computes the minimax decision, skipping branches that cannot improve the choice. It uses recursive depth-first search with two bounds, $\alpha$ and $\beta$, to decide when to stop exploring a branch.

The bounds summarize alternatives already available along the current path:

- $\alpha$: the best value already available to MAX.
- $\beta$: the best value already available to MIN.

Initially:

$$
[\alpha,\beta]=[-\infty,+\infty].
$$

If the current node has value estimate $v$:

- **MAX-node:** update $\alpha\leftarrow\max(\alpha,v)$.
- **MIN-node:** update $\beta\leftarrow\min(\beta,v)$.

The pruning condition is:

$$
\boxed{\alpha\geq\beta}
$$

For example, if MAX can already obtain $3$ from one move and MIN can force at most $2$ after another, MAX can discard the second move without examining its remaining outcomes.

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Result | same minimax value; tied moves may differ |
| Time, worst ordering | $O(b^m)$ |
| Time, ideal ordering | $O(b^{m/2})$ |
| Time, random ordering | typically $O(b^{3m/4})$, as estimated in the slides |
| Advantages | skips irrelevant branches without changing the minimax value |
| Disadvantages | efficiency depends strongly on move ordering |

Explore promising moves first to increase pruning. Move ordering can use game-specific rules or patterns learned from game data.

### Heuristic Minimax (H-Minimax)

The algorithm selects the move with the best estimated minimax value, stopping at a cutoff depth. It uses recursive depth-first search and an evaluation function to score positions at the cutoff.

The recurrence is:

$$
\mathrm{H\text{-}MINIMAX}(s,d)=
\begin{cases}
\mathrm{EVAL}(s), & \mathrm{IS\text{-}CUTOFF}(s,d),\\
\max\limits_{a\in A(s)}\mathrm{H\text{-}MINIMAX}(T(s,a),d+1), & \mathrm{TO\text{-}MOVE}(s)=\mathrm{MAX},\\
\min\limits_{a\in A(s)}\mathrm{H\text{-}MINIMAX}(T(s,a),d+1), & \mathrm{TO\text{-}MOVE}(s)=\mathrm{MIN}.
\end{cases}
$$

The cutoff test includes terminal states, where:

$$
\boxed{\mathrm{EVAL}(s)=\mathrm{UTILITY}(s)}
$$

\bigskip
> ***Evaluation Functions***

A simple chess heuristic is the material balance:

$$
\mathrm{EVAL}(s)=M_{\mathrm{MAX}}(s)-M_{\mathrm{MIN}}(s),
$$

where each player's material score is:

$$
M_p(s)=\#\text{pawns}+3\#\text{knights}+3\#\text{bishops}
+5\#\text{rooks}+9\#\text{queens}.
$$

Piece values also depend on position and game phase. The evaluation is an estimate, so a depth cutoff does not guarantee the optimal move.

\bigskip
> ***Horizon Effect***

The ***HORIZON EFFECT*** occurs when a significant outcome lies just beyond the cutoff. The agent may prefer moves that delay an unavoidable loss beyond its search depth, even if those moves make the final outcome worse.

Possible remedies are:

- **Quiescence search:** extend search until the position has no imminent changes that would strongly affect evaluation.
- **Singular extensions:** extend search for moves that are clearly better than the alternatives.

\bigskip
> ***Further Improvements***

- **Forward pruning:** consider only promising moves, or search less deeply through weaker moves. This can discard a good move.
- **Lookup tables:** store known moves or values for recurring positions, openings and endings.

### Monte Carlo Tree Search (MCTS)

The algorithm estimates move quality through repeated simulations, concentrating exploration on promising alternatives. It stores a search tree with visit counts and simulation results to guide later simulations.

The approach presented in the slides is:

1. Simulate games using a random or learned move policy.
2. Estimate the win rate of candidate moves.
3. Use the simulation results to select a move.

The policy may be learned from game data or self-play. Search can allocate more simulations to selected positions.

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Advantages | useful when the branching factor is very large |
| Disadvantages | estimates depend on simulation quality and available budget |

## Stochastic Games

A stochastic game includes random events that affect available moves or their outcomes. Randomness is represented by ***CHANCE*** nodes, which choose outcome $r$ with probability $P(r\mid s)$.

Examples include backgammon and Yahtzee. Random outcomes may be fully observable: stochasticity does not imply hidden information.

### Expectiminimax

The algorithm selects the move with the best expected outcome, considering both the opponent's choices and random events. It uses recursive search with maximum values at MAX-nodes, minimum values at MIN-nodes and weighted averages at CHANCE-nodes.

The terminal, MAX and MIN cases are the same as minimax. At a CHANCE-node:

$$
\boxed{\mathrm{EXMINIMAX}(s)=
\sum_{r\in A(s)}P(r\mid s)\,
\mathrm{EXMINIMAX}(T(s,r))}
$$

where:

$$
\sum_{r\in A(s)}P(r\mid s)=1.
$$

\bigskip
> ***Evaluation Functions***

Expected values depend on the numerical utility values, not only on which outcomes rank higher. Changing the scale nonlinearly can therefore change the selected move.

Bounds on minimum and maximum utility can help prune CHANCE-nodes by bounding the contribution of unexplored outcomes.

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Advantages | accounts for random outcomes and their probabilities |
| Disadvantages | chance outcomes greatly increase the search tree |

For example, two dice generate $36$ ordered outcomes per roll. Shallower search or ignoring unlikely outcomes can reduce cost, introducing approximation.

## Partially Observable Games

A partially observable game hides some information about the current state. Card games are a typical example.

### Averaging over Clairvoyance

The algorithm evaluates moves by solving possible states as if each were fully observable. It averages the resulting values to estimate move quality under uncertainty.

This approximation can suggest a plan that requires information the player does not actually have.

\bigskip
> ***Example***

- **Road A:** guarantees one gold coin.
- **Road B:** leads to a fork with two gold coins on one side and death on the other.
- **Known location:** choose Road B and then the safe side.
- **Unknown location:** the player cannot choose the safe side with certainty.

Averaging solutions that assume the safe side is known overvalues Road B.

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Advantages | relatively inexpensive approximation |
| Disadvantages | ignores the player's information state; does not properly model bluffing |

Belief states can represent the player's actual information, but increase time and memory requirements.

## Search Strategies: Summary

| **Problem** | **Main Approach** | **Key Idea** |
| - | - | - |
| Find an action sequence | state-space search | explore paths from the initial state |
| Optimize a configuration | local search | improve the objective value |
| Handle multiple action outcomes | AND-OR search | solve every possible outcome |
| Handle incomplete observation | belief-state search | search over sets of possible states |
| Explore an unknown environment | online search | interleave learning and acting |
| Play against an opponent | minimax | maximize the guaranteed outcome |
| Reduce game-tree exploration | alpha-beta pruning | discard branches that cannot affect the choice |
| Play with limited search depth | H-minimax | evaluate positions at a cutoff |
| Handle random events | expectiminimax | average chance outcomes by probability |
| Approximate hidden information | averaging over clairvoyance | average fully observable solutions |
