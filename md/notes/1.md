# Searching Problems

A searching problem can be formulated as a search for a path from an initial state to a goal state. This formulation assumes the environment is fully observable, deterministic, static, and discrete.

## Problem Formulation

A search problem is defined as:

$$
\boxed{\mathcal P=(S,s_0,G,A,T,c)}
$$

where:

- $S$ is the set of states.
- $s_0\in S$ is the initial state.
- $G\subseteq S$ is the set of goal states.
- $A(s)$ is the set of applicable actions in state $s$.
- $T(s,a)\in S$, for $a\in A(s)$, is the successor state.
- $c(s,a,s')$ is the cost of transitioning from $s$ to $s'$ via $a$.

Assuming $A$ is the global action set and $T$ is restricted to applicable state-action pairs, ***DETERMINISM*** follows from the fact that:

$$
T:S\times A\to S
$$

is a single-valued function.

\bigskip
> ***Paths***

A path is a sequence:

$$
\pi=(s_0,a_0,s_1,a_1,\ldots,a_{n-1},s_n)
$$

such that:

$$
\forall i\in\{0,\ldots,n-1\}:
\quad a_i\in A(s_i),\quad s_{i+1}=T(s_i,a_i)
$$

A path is a solution if:

$$
s_n\in G
$$

Its total cost is:

$$
\boxed{C(\pi)=\sum_{i=0}^{n-1}c(s_i,a_i,s_{i+1})}
$$

A solution $\pi^*$ is ***OPTIMAL*** if:

$$
\boxed{\pi^*\in\arg\min_{\pi\in\Pi_G}C(\pi)}
$$

where $\Pi_G$ denotes the set of all solution paths.

### Evaluation

A search algorithm $\mathcal{A}$ is evaluated according to four criteria:

- **Completeness:** whether $\mathcal{A}$ finds a solution whenever one exists.
- **Optimality:** whether $\mathcal{A}$ returns a minimum-cost solution.
- **Time Complexity:** number of nodes generated or expanded.
- **Space Complexity:** maximum number of nodes stored in memory.

We will use $b$ for the branching factor, $d$ for the depth of the shallowest solution, and $m$ for the maximum depth of the search tree.

## Uninformed Search

A search is uninformed if it uses only the problem definition, without any estimate of how close a state is to the goal.

The Python pseudocode uses the same abstract operations as the slides: `Node` creates a search node, `expand` generates its children, and `is_cycle` checks its ancestor path. Nodes store `state`, path cost `g` (initially zero), and `depth` (initially zero). `PriorityQueue` pops the node with the smallest key; `peek` reads it without removal. `None` means failure; `"cutoff"` means the depth limit was reached. Heuristics `h` take a node. For bidirectional search, `join_nodes` joins the two paths in forward order, and `terminated` checks the stopping condition for the chosen search strategy.

### Breadth-First Search (BFS)

The algorithm expands nodes in order of increasing depth, exploring the shallowest nodes first. It uses a FIFO queue to store the frontier.

If the shallowest solution is at depth $d$, the number of nodes grows as:

$$
1+b+b^2+\cdots+b^d=O(b^d)
$$

\bigskip
> ***Pseudocode***

```py
def bfs(problem):
    node = Node(problem.initial)
    if problem.is_goal(node.state):
        return node
    frontier, reached = deque([node]), {node.state}
    while frontier:
        for child in expand(problem, frontier.popleft()):
            if problem.is_goal(child.state):
                return child
            if child.state not in reached:
                reached.add(child.state)
                frontier.append(child)
    return None
```

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Complete | $\text{Yes}^{1}$ |
| Optimal | $\text{Yes}^{3}$ |
| Space | $O(b^d)$ |
| Time | $O(b^d)$ |
| Advantages | finds shallowest solution |
| Disadvantages | high memory usage |

***Assumptions:***

- (1) complete if $b$ is finite, and the state space either has a solution or is finite.
- (3) cost-optimal if action costs are identical.

### Uniform-Cost Search (UCS)

The algorithm expands nodes in order of increasing path cost, exploring the cheapest paths first. It uses a priority queue ordered by $g(n)$ to store the frontier.

It is equivalent to Dijkstra's algorithm when applied to shortest-path search with non-negative edge costs:

$$
f(n)=g(n)
$$

where $g(n)$ is the cost from the initial state to node $n$.

\bigskip
> ***Pseudocode***

```py
def best_first_search(problem, f):
    node = Node(problem.initial)
    frontier = PriorityQueue([node], key=f)
    reached = {node.state: node}
    while frontier:
        node = frontier.pop()
        if problem.is_goal(node.state):
            return node
        for child in expand(problem, node):
            s = child.state
            if s not in reached or child.g < reached[s].g:
                reached[s] = child
                frontier.add(child)
    return None


def ucs(problem):
    return best_first_search(problem, lambda n: n.g)
```

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Complete | $\text{Yes}^{1,2}$ |
| Optimal | $\text{Yes}$ |
| Space | $O(b^{1+\lfloor C^*/\varepsilon\rfloor})$ |
| Time | $O(b^{1+\lfloor C^*/\varepsilon\rfloor})$ |
| Advantages | finds the least-cost solution |
| Disadvantages | high time and memory usage |

***Assumptions:***

- (1) complete if $b$ is finite, and the state space either has a solution or is finite.
- (2) complete if all action costs are $\geq \varepsilon > 0$.

### Depth-First Search (DFS)

The algorithm expands nodes in order of decreasing depth, following a branch as far as possible before backtracking. It uses a LIFO stack to store the frontier.

If $b$ is the branching factor and $m$ is the maximum depth, the number of nodes explored can grow exponentially:

$$
1+b+b^2+\cdots+b^m=O(b^m)
$$

\bigskip
> ***Pseudocode***

```py
def dfs(problem):
    return dls(problem, float("inf"))
```

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Complete | $\text{No}$ |
| Optimal | $\text{No}$ |
| Time | $O(b^m)$ |
| Space | $O(bm)$ |
| Advantages | low memory usage |
| Disadvantages | can get stuck in infinite branches |

### Depth-Limited Search (DLS)

The algorithm expands nodes in order of decreasing depth, following a branch up to a fixed depth limit $\ell$ before backtracking. It uses a LIFO stack to store the frontier.

The number of nodes explored is bounded by:

$$
1+b+b^2+\cdots+b^\ell=O(b^\ell)
$$

\bigskip
> ***Pseudocode***

```py
def dls(problem, limit):
    frontier = [Node(problem.initial)]
    result = None
    while frontier:
        node = frontier.pop()
        if problem.is_goal(node.state):
            return node
        if node.depth >= limit:
            result = "cutoff"
        elif not is_cycle(node):
            frontier.extend(expand(problem, node))
    return result
```

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Complete | $\text{No}$ |
| Optimal | $\text{No}$ |
| Time | $O(b^\ell)$ |
| Space | $O(b\ell)$ |
| Advantages | avoids infinite-depth exploration |
| Disadvantages | may miss solutions beyond the limit |

### Iterative-Deepening Search (IDS)

The algorithm repeatedly explores the search tree with increasing depth limits, restarting from the initial node until a solution is found. It uses depth-limited DFS at each iteration, storing only the current path and its unexplored alternatives.

The depth limits are:

$$
\ell=0,1,2,\ldots,d
$$

Although nodes are explored multiple times, the asymptotic time complexity remains:

$$
1+b+b^2+\cdots+b^d=O(b^d)
$$

\bigskip
> ***Pseudocode***

```py
def ids(problem):
    for depth in count():
        result = dls(problem, depth)
        if result != "cutoff":
            return result
```

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Complete | $\text{Yes}^1$ |
| Optimal | $\text{Yes}^3$ |
| Time | $O(b^d)$ |
| Space | $O(bd)$ |
| Advantages | low memory usage |
| Disadvantages | repeated exploration of shallow nodes |

***Assumptions:***

- (1) complete if $b$ is finite, and the state space either has a solution or is finite.
- (3) cost-optimal if action costs are identical.

### Bidirectional Search

The algorithm searches forward from the initial state and backward from the goal, looking for a state reached by both searches. It uses a separate frontier for each direction, with a FIFO queue for each when both searches use BFS.

Each search explores approximately half the solution depth:

$$
b^{d/2}+b^{d/2}\ll b^d
$$

It is applicable when the goal state is known, backward transitions can be generated, and the intersection between the two frontiers can be detected efficiently.

\bigskip
> ***Pseudocode***

```py
def bidirectional_search(p_f, f_f, p_b, f_b):
    n_f, n_b = Node(p_f.initial), Node(p_b.initial)
    q_f = PriorityQueue([n_f], key=f_f)
    q_b = PriorityQueue([n_b], key=f_b)
    r_f, r_b = {n_f.state: n_f}, {n_b.state: n_b}
    solution = None
    if n_f.state == n_b.state:
        return n_f
    while not terminated(solution, q_f, q_b):
        if f_f(q_f.peek()) < f_b(q_b.peek()):
            solution = proceed("F", p_f, q_f, r_f, r_b, solution)
        else:
            solution = proceed("B", p_b, q_b, r_b, r_f, solution)
    return solution


def proceed(direction, problem, frontier, reached, other, solution):
    for child in expand(problem, frontier.pop()):
        s = child.state
        if s not in reached or child.g < reached[s].g:
            reached[s] = child
            frontier.add(child)
            if s in other:
                candidate = join_nodes(direction, child, other[s])
                if solution is None or candidate.g < solution.g:
                    solution = candidate
    return solution
```

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Complete | $\text{Yes}^{1,4}$
| Optimal | $\text{Yes}^{3,4}$ |
| Space | $O(b^{d/2})$ |
| Time | $O(b^{d/2})$ |
| Advantages | much faster than BFS for large $d$ |
| Disadvantages | high memory usage |

***Assumptions:***

- (1) complete if $b$ is finite, and the state space either has a solution or is finite.
- (3) cost-optimal if action costs are identical.
- (4) if both directions are breadth-first or uniform-cost.

## Informed Search

A search is informed if it uses a heuristic function:

$$
h:S\to\mathbb{R}_{\geq 0}
$$

to guide the search toward promising states, reducing unnecessary exploration.

\bigskip
> ***Admissible Heuristics***

Let $h^*(s)$ be the true minimum cost from $s$ to a goal. A heuristic is ***ADMISSIBLE*** if it never overestimates the actual cost:

$$
\boxed{\forall s\in S:\quad 0\leq h(s)\leq h^*(s)}
$$

An admissible heuristic is always optimistic, but not necessarily accurate.

### A* Search

The algorithm expands nodes in order of increasing estimated total cost, exploring the most promising paths first. It uses a priority queue ordered by $f(n)$ to store the frontier.

The estimated total cost is:

$$
f(n)=g(n)+h(n)
$$

where:

- $g(n)$ is the cost from the initial state to node $n$.
- $h(n)$ is the heuristic estimate from $n$ to a goal.
- $f(n)$ is the estimated total cost of a solution through $n$.


\bigskip
> ***Pseudocode***

```py
def a_star(problem, h):
    return best_first_search(problem, lambda n: n.g + h(n))
```

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Complete | $\text{Yes}$ |
| Optimal | $\text{Yes}^1$ |
| Advantages | heuristic-guided exploration |
| Disadvantages | high memory usage |

***Assumptions:***

- (1) optimal if $h$ is admissible.

\bigskip
> ***$\boxed{\text{PROOF (1)}}$***

Assume $h$ is admissible and A* returns a suboptimal solution of cost $C>C^*$, where $C^*$ is the optimal cost.

Before selecting that suboptimal goal, there must be a node $n$ on an optimal path still in the frontier, reached with its optimal cost $g^*(n)$.

Since A* selects the node with minimum $f$, selecting the suboptimal goal implies:

$$
C\leq f(n)
$$

However, by definition:

$$
f(n)=g^*(n)+h(n)
$$

Since $h$ is admissible:

$$
h(n)\leq h^*(n)
$$

Therefore, because $n$ lies on an optimal path:

$$
f(n)\leq g^*(n)+h^*(n)=C^*
$$

Combining the inequalities:

$$
\boxed{C\leq f(n)\leq C^*<C}
$$

This is ***IMPOSSIBLE***.

Hence A* cannot return a suboptimal solution under the stated assumptions.

$$
\boxed{C=C^*}
$$

### IDA* (Iterative-Deepening A*)

The algorithm repeatedly explores the search tree with increasing cost limits, skipping nodes whose estimated total cost exceeds the current limit. It uses depth-first search at each iteration, storing only the current path and its unexplored alternatives.

The estimated total cost is:

$$
f(n)=g(n)+h(n)
$$

If no solution is found, the cost limit increases to the smallest $f$-value that exceeded the previous limit.

\bigskip
> ***Pseudocode***

```py
def ida_star(problem, h):
    def search(node, limit):
        f = node.g + h(node)
        if f > limit:
            return None, f
        if problem.is_goal(node.state):
            return node, f
        next_limit = float("inf")
        if not is_cycle(node):
            for child in expand(problem, node):
                result, cost = search(child, limit)
                if result is not None:
                    return result, cost
                next_limit = min(next_limit, cost)
        return None, next_limit

    root = Node(problem.initial)
    limit = h(root)
    while limit < float("inf"):
        result, limit = search(root, limit)
        if result is not None:
            return result
    return None
```

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Complete | $\text{Yes}$ |
| Optimal | $\text{Yes}^1$ |
| Advantages | low memory usage |
| Disadvantages | high time usage |

***Assumptions:***

- (1) optimal if $h$ is admissible.

### Recursive Best-First Search (RBFS)

The algorithm follows the path with the lowest estimated total cost, backtracking when another path becomes more promising. It uses recursive depth-first search, remembering the best alternative cost at each level to decide when to backtrack.

\bigskip
> ***Pseudocode***

```py
def rbfs(problem, h):
    def search(node, limit):
        if problem.is_goal(node.state):
            return node, node.f
        successors = list(expand(problem, node))
        if not successors:
            return None, float("inf")
        for child in successors:
            child.f = max(child.g + h(child), node.f)
        while True:
            successors.sort(key=lambda n: n.f)
            best = successors[0]
            if best.f > limit or best.f == float("inf"):
                return None, best.f
            alternative = (successors[1].f if len(successors) > 1
                           else float("inf"))
            result, best.f = search(best, min(limit, alternative))
            if result is not None:
                return result, best.f

    root = Node(problem.initial)
    root.f = h(root)
    return search(root, float("inf"))[0]
```

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Complete | $\text{Yes}$ |
| Optimal | $\text{Yes}^1$ |
| Advantages | low memory usage |
| Disadvantages | high time usage |

***Assumptions:***

- (1) optimal if $h$ is admissible.

## Local Search

A local search problem asks for a configuration that maximizes an objective function. The solution is the configuration itself, regardless of the path used to reach it.

The problem is defined by:

- $S$: the set of configurations.
- $N(s)$: the neighbours of configuration $s$.
- $V:S\to\mathbb R$: the objective function to maximize.

For example, the $n$-queens problem asks for a placement of $n$ queens on an $n\times n$ chessboard such that no queen attacks another. If $c(s)$ counts conflicts, a possible objective is:

$$
\boxed{V(s)=-c(s)}
$$

Local search usually stores only the current configuration, or a small set of configurations.

### Hill Climbing

The algorithm selects the neighbour with the highest objective value, stopping when no neighbour improves the current state. It stores only the current state and evaluates its neighbours at each step.

The update rule is:

$$
s'\in\arg\max_{u\in N(s)}V(u),
\qquad s\leftarrow s'\quad\text{if }V(s')>V(s).
$$

\bigskip
> ***Pseudocode***

Here `neighbours` generates nearby configurations, and `value` is the objective function.

```py
def hill_climbing(state, neighbours, value):
    while True:
        next_state = max(neighbours(state), key=value, default=state)
        if value(next_state) <= value(state):
            return state
        state = next_state
```

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Complete | No, in general |
| Optimal | No, in general |
| Advantages | simple; low memory usage |
| Disadvantages | can stop before reaching a global maximum |

\bigskip
> ***Local Optima***

Hill climbing can get stuck in:

- **Local maximum:** a state better than its neighbours, but worse than the global maximum.
- **Plateau:** a region where neighbouring states have the same objective value.
- **Ridge:** a region where progress requires a sequence of moves that are not individually improving.

\bigskip
> ***Variants***

- **Sideways moves:** allow moves with unchanged objective value to cross plateaus.
- **Stochastic:** randomly select an improving neighbour.
- **First-choice:** generate random neighbours until an improving one is found.
- **Random-restart:** restart from a random state when progress stops, keeping the best state found.

### Simulated Annealing

The algorithm selects a random neighbour, accepting improvements and sometimes accepting worse states. It stores only the current state and uses a decreasing temperature to control the probability of accepting worse moves.

Let:

$$
\Delta=V(s')-V(s).
$$

The acceptance probability is:

$$
\boxed{
P(\text{accept }s')=
\begin{cases}
1, & \Delta\geq 0,\\
e^{\Delta/T}, & \Delta<0.
\end{cases}}
$$

where $T>0$ is the ***TEMPERATURE***.

- **High temperature:** worse moves are more likely, allowing exploration.
- **Low temperature:** worse moves are less likely, favouring improvement.

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Advantages | can escape local maxima and plateaus |
| Disadvantages | performance depends on the cooling schedule |

### Local Beam Search

The algorithm generates the neighbours of all current states, keeping the $k$ best configurations for the next step. It stores a set of $k>1$ states and selects their successors together.

If the current set is $B_t$, the next set is:

$$
B_{t+1}=\operatorname{Top}_k\left(\bigcup_{s\in B_t}N(s)\right).
$$

where $\operatorname{Top}_k$ selects the $k$ configurations with the highest objective values.

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Advantages | shares information between search paths |
| Disadvantages | states can become too similar, reducing diversity |

Stochastic variants select successors probabilistically to preserve diversity.

### Evolutionary Algorithms

The algorithm generates new configurations by combining and randomly modifying selected configurations. It stores a population of candidates, using fitness to guide the selection of parents.

The main steps are:

1. Generate a random initial population.
2. Select parents according to their fitness.
3. Combine parents through ***CROSSOVER*** to generate children.
4. Randomly modify children through ***MUTATION***.
5. Optionally retain the best parents through ***ELITISM***.

Repeat until the stopping condition is satisfied, then return the best configuration found. The slides use lack of further fitness improvement as a stopping condition.

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Advantages | can combine useful parts of different configurations |
| Disadvantages | depends strongly on representation and crossover |

A useful crossover should preserve good contributions from both parents. For numerical configurations, averaging may be more meaningful than mixing their binary encodings.

### Continuous Search Spaces

A continuous configuration is represented as:

$$
x=(x_1,\ldots,x_n)\in\mathbb R^n.
$$

If the objective function is sufficiently smooth, optimization can use:

- **Gradient ascent/descent:** move in the direction of increasing/decreasing objective value.
- **Newton--Raphson:** use local derivative information to compute updates.

With constraints, the problem becomes ***CONSTRAINED OPTIMIZATION***. Convex problems admit efficient methods under suitable assumptions.

If the objective and constraints are linear, the problem is ***LINEAR PROGRAMMING***. Polynomial-time algorithms exist; the simplex method is widely used, but has exponential worst-case complexity.

## Search with Nondeterministic Actions

An action is nondeterministic if it can produce more than one successor state. Its possible outcomes are represented by:

$$
\boxed{\mathrm{RESULTS}(s,a)\subseteq S,
\qquad\mathrm{RESULTS}(s,a)\neq\varnothing}
$$

A solution must specify what to do after each possible outcome. This is a ***CONDITIONAL PLAN***.

For example, in the nondeterministic Vacuum World:

$$
\mathrm{RESULTS}(1,\texttt{suck})=\{5,8\}.
$$

A conditional plan from state $1$ is:

```text
[suck, if state = 5 then [right, suck] else []]
```

### AND-OR Search

The algorithm searches for an action whose possible outcomes can all be solved, building a conditional plan. It uses OR-nodes for action choices and AND-nodes for their possible outcomes.

The two node types are:

- **OR-node:** choose at least one solvable successor.
- **AND-node:** solve every successor.

\bigskip
> ***Solution***

A solution is a subtree such that:

1. It contains the root.
2. Every leaf is a goal.
3. Every OR-node includes at least one successor.
4. Every AND-node includes all successors.

If an action has outcomes $s_1,\ldots,s_k$, with plans $p_1,\ldots,p_k$, combine them as:

```text
if state = s1 then p1
else if state = s2 then p2
...
else if state = sk then pk
```

Depth-first, breadth-first and heuristic search ideas can be adapted to AND-OR trees. In the depth-first method from the slides, a state repeated on the current path causes that branch to fail.

***Assumptions:***

- This method searches for finite, acyclic conditional plans. Plans that rely on repeatedly trying an action require a different treatment of cycles.

## Search with Incomplete Observation

When the agent cannot identify its physical state, it searches over sets of possible states. Each set is a ***BELIEF STATE***:

$$
\boxed{b\subseteq S}
$$

### Search with No Observation

A sensorless agent must find an action sequence that reaches a goal regardless of the actual initial state.

The search problem is defined by:

- **States:** belief states $b\subseteq S$.
- **Initial state:** all physical states compatible with the initial information.
- **Actions:** actions available in at least one possible state.
- **Transitions:** all possible successors of the current belief state.
- **Goal:** every remaining possible state is a goal.

Assuming illegal actions leave the state unchanged:

$$
A(b)=\bigcup_{s\in b}A(s).
$$

Extend $T(s,a)=s$ to actions illegal in $s$. For deterministic physical transitions:

$$
\boxed{T(b,a)=\{T(s,a)\mid s\in b\}}
$$

The goal condition is:

$$
\boxed{b\subseteq G}
$$

For nondeterministic physical transitions, take the union of all possible outcomes instead.

\bigskip
> ***Evaluation***

- With $N$ physical states, there are up to $2^N$ belief states.
- Not every belief state is reachable or relevant.
- If a plan solves $b$, the same plan solves every $b'\subseteq b$.
- Logical representations can be more compact than explicit sets.
- Action costs may use worst-case or expected cost, depending on the problem.

An alternative is ***INCREMENTAL BELIEF-STATE SEARCH***: find a plan for one possible initial state, check it against the others, and refine the search when it fails.

### Search with Partial Observation

With partial observation, an action changes the physical state and a percept reduces uncertainty. The belief state is updated through three steps:

1. **Predict:** compute possible states after the action.
2. **Percept:** determine which observations are possible.
3. **Update:** retain only states compatible with the received observation.

Formally:

$$
\begin{aligned}
\mathrm{Predict}(b,a)&=\hat b=\{T(s,a)\mid s\in b\},\\
\mathrm{PossiblePercepts}(\hat b)&=\{\mathrm{Percept}(s)\mid s\in\hat b\},\\
\mathrm{Update}(\hat b,o)&=\{s\in\hat b\mid\mathrm{Percept}(s)=o\}.
\end{aligned}
$$

Different percepts produce different successor belief states:

$$
\boxed{\mathrm{RESULTS}(b,a)=
\{\mathrm{Update}(\hat b,o)\mid o\in\mathrm{PossiblePercepts}(\hat b)\}}
$$

where $\hat b=\mathrm{Predict}(b,a)$.

Actions are therefore nondeterministic at the belief-state level, even when physical transitions are deterministic. AND-OR search can build a plan for every possible percept.

## Online Search

An online agent alternates computation, observation and action while exploring an unknown environment. It learns transition outcomes and costs by executing actions.

***Assumptions:***

- The environment is deterministic and observable.
- $A(s)$ gives the legal actions in the current state.
- The successor $s'$ and cost $c(s,a,s')$ become known after trying $a$.
- The agent can test whether its current state is a goal.

\bigskip
> ***Competitive Ratio***

The cost of exploration is measured by:

$$
\boxed{\text{Competitive ratio}=
\frac{\text{total cost of the executed path}}{\text{cost of an optimal path}}}
$$

The executed path includes exploration and backtracking. Even with reversible actions, an unknown environment can make this ratio arbitrarily large.

If actions are irreversible, the agent may enter a ***DEAD END*** from which the goal is unreachable.

### Online Depth-First Search

The algorithm tries unexplored actions, returning to earlier states when no unexplored action remains. It stores observed transitions and the actions still to try in each visited state.

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Complete | Yes, under the assumptions below |
| Optimal | No |
| Advantages | systematically explores an unknown environment |
| Disadvantages | competitive ratio can be arbitrarily large |

***Assumptions:***

- A finite reachable state space, reversible actions and a reachable goal.

### Online Hill Climbing

The algorithm selects an action that improves its heuristic estimate of distance to the goal. It uses the current state and the heuristic to guide each move.

Unlike offline local search, the agent cannot freely restart from a random state: it must physically execute actions to move elsewhere. A local minimum can therefore block progress.

### Random Walk

The algorithm chooses a random untried action when one is available, otherwise choosing a random legal action. It uses random choices to continue exploration when no heuristic improvement is available.

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Complete | With probability $1$, under the assumptions below |
| Optimal | No |
| Advantages | simple; can escape local minima |
| Disadvantages | expected exploration cost can be exponential |

***Assumptions:***

- A finite reachable state space, reversible actions and a reachable goal.
- Every available action has a positive probability of selection.

### Learning Real-Time A* (LRTA*)

The algorithm chooses the action with the lowest estimated cost to the goal, updating its estimates as it explores. It stores observed transitions and a table $H(s)$ of estimated remaining costs.

When a state is first visited:

$$
H(s)\leftarrow h(s).
$$

After executing $a$ in $s$ and observing $s'$:

1. Record the transition $\mathrm{result}[s,a]=s'$.
2. Update the estimate of the previous state $s$.
3. Choose the next action from the current state $s'$.

The update is:

$$
\boxed{H(s)\leftarrow\min_{a\in A(s)}
\mathrm{LRTA\text{-}Cost}(s,a,\mathrm{result}[s,a])}
$$

where:

$$
\mathrm{LRTA\text{-}Cost}(s,a,u)=
\begin{cases}
h(s), & \text{if the successor }u\text{ is unknown},\\
c(s,a,u)+H(u), & \text{otherwise}.
\end{cases}
$$

The next action minimizes the same cost estimate at $s'$. Updating $H$ can make an apparent local minimum less attractive, allowing the agent to leave it.

## Adversarial Search

An adversarial search problem involves agents with conflicting objectives. The basic model is a two-player, zero-sum game with deterministic actions and perfect information.

***Assumptions:***

- **MAX** wants to maximize the final score.
- **MIN** wants to minimize the same score.
- The game ends after finitely many moves.

A game is defined by:

- $s_0$: the initial state.
- $\mathrm{TO\text{-}MOVE}(s)$: the player whose turn it is.
- $A(s)$: the legal moves.
- $T(s,a)$: the state after move $a$.
- $\mathrm{IS\text{-}TERMINAL}(s)$: the terminal-state test.
- $\mathrm{UTILITY}(s)$: the final score from MAX's perspective.

### Minimax Search

The algorithm selects the move with the best guaranteed outcome, assuming the opponent also plays optimally. It uses recursive depth-first search, propagating maximum values at MAX-nodes and minimum values at MIN-nodes.

The minimax value is:

$$
\boxed{\mathrm{MINIMAX}(s)=
\begin{cases}
\mathrm{UTILITY}(s), & s\text{ is terminal},\\
\max\limits_{a\in A(s)}\mathrm{MINIMAX}(T(s,a)), & \mathrm{TO\text{-}MOVE}(s)=\mathrm{MAX},\\
\min\limits_{a\in A(s)}\mathrm{MINIMAX}(T(s,a)), & \mathrm{TO\text{-}MOVE}(s)=\mathrm{MIN}.
\end{cases}}
$$

\bigskip
> ***Pseudocode***

As in the slides, the recursive functions return `(value, move)`. Here the root player is MAX, and `game.utility` returns the score from MAX's perspective.

```py
def minimax(game, state):
    return max_value(game, state)[1]


def max_value(game, state):
    if game.is_terminal(state):
        return game.utility(state), None
    value, move = -float("inf"), None
    for action in game.actions(state):
        score, _ = min_value(game, game.result(state, action))
        if score > value:
            value, move = score, action
    return value, move


def min_value(game, state):
    if game.is_terminal(state):
        return game.utility(state), None
    value, move = float("inf"), None
    for action in game.actions(state):
        score, _ = max_value(game, game.result(state, action))
        if score < value:
            value, move = score, action
    return value, move
```

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Complete | Yes, for a finite game tree |
| Optimal | Yes, against an optimal opponent |
| Time | $O(b^m)$ |
| Space | $O(bm)$; $O(m)$ with successors generated one at a time |
| Advantages | finds the best guaranteed outcome |
| Disadvantages | explores an exponentially large game tree |

Here $b$ is the branching factor and $m$ is the maximum game-tree depth. In chess, typical estimates are $b\approx35$ and a game length of about $80$ moves, making exhaustive search impractical.

\bigskip
> ***Multiplayer Games***

With more than two players, use $\mathrm{UTILITY}(s,p)$ for each player $p$ and propagate vectors of scores. Each player chooses according to its own score; alliances may arise.

### Alpha-Beta Pruning

The algorithm computes the minimax decision, skipping branches that cannot improve the choice. It uses recursive depth-first search with two bounds, $\alpha$ and $\beta$, to decide when to stop exploring a branch.

The bounds summarize alternatives already available along the current path:

- $\alpha$: the best value already available to MAX.
- $\beta$: the best value already available to MIN.

Initially:

$$
[\alpha,\beta]=[-\infty,+\infty].
$$

If the current node has value estimate $v$:

- **MAX-node:** update $\alpha\leftarrow\max(\alpha,v)$.
- **MIN-node:** update $\beta\leftarrow\min(\beta,v)$.

The pruning condition is:

$$
\boxed{\alpha\geq\beta}
$$

For example, if MAX can already obtain $3$ from one move and MIN can force at most $2$ after another, MAX can discard the second move without examining its remaining outcomes.

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Result | same minimax value; tied moves may differ |
| Time, worst ordering | $O(b^m)$ |
| Time, ideal ordering | $O(b^{m/2})$ |
| Time, random ordering | typically $O(b^{3m/4})$, as estimated in the slides |
| Advantages | skips irrelevant branches without changing the minimax value |
| Disadvantages | efficiency depends strongly on move ordering |

Explore promising moves first to increase pruning. Move ordering can use game-specific rules or patterns learned from game data.

### Heuristic Minimax (H-Minimax)

The algorithm selects the move with the best estimated minimax value, stopping at a cutoff depth. It uses recursive depth-first search and an evaluation function to score positions at the cutoff.

The recurrence is:

$$
\mathrm{H\text{-}MINIMAX}(s,d)=
\begin{cases}
\mathrm{EVAL}(s), & \mathrm{IS\text{-}CUTOFF}(s,d),\\
\max\limits_{a\in A(s)}\mathrm{H\text{-}MINIMAX}(T(s,a),d+1), & \mathrm{TO\text{-}MOVE}(s)=\mathrm{MAX},\\
\min\limits_{a\in A(s)}\mathrm{H\text{-}MINIMAX}(T(s,a),d+1), & \mathrm{TO\text{-}MOVE}(s)=\mathrm{MIN}.
\end{cases}
$$

The cutoff test includes terminal states, where:

$$
\boxed{\mathrm{EVAL}(s)=\mathrm{UTILITY}(s)}
$$

\bigskip
> ***Evaluation Functions***

A simple chess heuristic is the material balance:

$$
\mathrm{EVAL}(s)=M_{\mathrm{MAX}}(s)-M_{\mathrm{MIN}}(s),
$$

where each player's material score is:

$$
M_p(s)=\#\text{pawns}+3\#\text{knights}+3\#\text{bishops}
+5\#\text{rooks}+9\#\text{queens}.
$$

Piece values also depend on position and game phase. The evaluation is an estimate, so a depth cutoff does not guarantee the optimal move.

\bigskip
> ***Horizon Effect***

The ***HORIZON EFFECT*** occurs when a significant outcome lies just beyond the cutoff. The agent may prefer moves that delay an unavoidable loss beyond its search depth, even if those moves make the final outcome worse.

Possible remedies are:

- **Quiescence search:** extend search until the position has no imminent changes that would strongly affect evaluation.
- **Singular extensions:** extend search for moves that are clearly better than the alternatives.

\bigskip
> ***Further Improvements***

- **Forward pruning:** consider only promising moves, or search less deeply through weaker moves. This can discard a good move.
- **Lookup tables:** store known moves or values for recurring positions, openings and endings.

### Monte Carlo Tree Search (MCTS)

The algorithm estimates move quality through repeated simulations, concentrating exploration on promising alternatives. It stores a search tree with visit counts and simulation results to guide later simulations.

The approach presented in the slides is:

1. Simulate games using a random or learned move policy.
2. Estimate the win rate of candidate moves.
3. Use the simulation results to select a move.

The policy may be learned from game data or self-play. Search can allocate more simulations to selected positions.

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Advantages | useful when the branching factor is very large |
| Disadvantages | estimates depend on simulation quality and available budget |

## Stochastic Games

A stochastic game includes random events that affect available moves or their outcomes. Randomness is represented by ***CHANCE*** nodes, which choose outcome $r$ with probability $P(r\mid s)$.

Examples include backgammon and Yahtzee. Random outcomes may be fully observable: stochasticity does not imply hidden information.

### Expectiminimax

The algorithm selects the move with the best expected outcome, considering both the opponent's choices and random events. It uses recursive search with maximum values at MAX-nodes, minimum values at MIN-nodes and weighted averages at CHANCE-nodes.

The terminal, MAX and MIN cases are the same as minimax. At a CHANCE-node:

$$
\boxed{\mathrm{EXMINIMAX}(s)=
\sum_{r\in A(s)}P(r\mid s)\,
\mathrm{EXMINIMAX}(T(s,r))}
$$

where:

$$
\sum_{r\in A(s)}P(r\mid s)=1.
$$

\bigskip
> ***Evaluation Functions***

Expected values depend on the numerical utility values, not only on which outcomes rank higher. Changing the scale nonlinearly can therefore change the selected move.

Bounds on minimum and maximum utility can help prune CHANCE-nodes by bounding the contribution of unexplored outcomes.

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Advantages | accounts for random outcomes and their probabilities |
| Disadvantages | chance outcomes greatly increase the search tree |

For example, two dice generate $36$ ordered outcomes per roll. Shallower search or ignoring unlikely outcomes can reduce cost, introducing approximation.

## Partially Observable Games

A partially observable game hides some information about the current state. Card games are a typical example.

### Averaging over Clairvoyance

The algorithm evaluates moves by solving possible states as if each were fully observable. It averages the resulting values to estimate move quality under uncertainty.

This approximation can suggest a plan that requires information the player does not actually have.

\bigskip
> ***Example***

- **Road A:** guarantees one gold coin.
- **Road B:** leads to a fork with two gold coins on one side and death on the other.
- **Known location:** choose Road B and then the safe side.
- **Unknown location:** the player cannot choose the safe side with certainty.

Averaging solutions that assume the safe side is known overvalues Road B.

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Advantages | relatively inexpensive approximation |
| Disadvantages | ignores the player's information state; does not properly model bluffing |

Belief states can represent the player's actual information, but increase time and memory requirements.

## Search Strategies: Summary

| **Problem** | **Main Approach** | **Key Idea** |
| - | - | - |
| Find an action sequence | state-space search | explore paths from the initial state |
| Optimize a configuration | local search | improve the objective value |
| Handle multiple action outcomes | AND-OR search | solve every possible outcome |
| Handle incomplete observation | belief-state search | search over sets of possible states |
| Explore an unknown environment | online search | interleave learning and acting |
| Play against an opponent | minimax | maximize the guaranteed outcome |
| Reduce game-tree exploration | alpha-beta pruning | discard branches that cannot affect the choice |
| Play with limited search depth | H-minimax | evaluate positions at a cutoff |
| Handle random events | expectiminimax | average chance outcomes by probability |
| Approximate hidden information | averaging over clairvoyance | average fully observable solutions |
