# Constraint Satisfaction

A constraint satisfaction problem asks for values of variables that satisfy a set of constraints. It uses a factored representation: states are assignments of values to variables.

## Problem Formulation

A constraint satisfaction problem is defined as:

$$
\boxed{\mathrm{CSP}=(X,D,C)}
$$

where:

- $X=\{X_1,\ldots,X_n\}$ is the set of variables.
- $D=\{D_1,\ldots,D_n\}$ gives the domain $D_i$ of each variable $X_i$.
- $C$ is the set of constraints.

The goal is to find a satisfying assignment. Optimization problems additionally maximize an objective or minimize a cost; here we focus on satisfaction.

### Constraints

A constraint is a pair:

$$
\boxed{C_j=\langle\mathrm{scope},\mathrm{rel}\rangle}
$$

where:

- **Scope:** the variables involved in the constraint.
- **Relation:** the allowed combinations of their values.

For example, if $D_1=D_2=\{1,2,3\}$, the constraint $X_1<X_2$ allows:

$$
\mathrm{rel}=\{(1,2),(1,3),(2,3)\}.
$$

### Assignments and Solutions

A ***PARTIAL ASSIGNMENT*** assigns values to some variables, with each value belonging to its variable's domain.

An assignment is:

- **Consistent:** it violates no constraint whose scope is fully assigned.
- **Complete:** it assigns every variable.
- **A solution:** it is complete and satisfies every constraint.

$$
\boxed{\text{Solution}=\text{Complete assignment}+\text{Consistency}}
$$

A consistent partial assignment does not necessarily extend to a solution.

### Examples

\bigskip
> ***Map Coloring***

Color Australia's regions so that neighbouring regions have different colors:

$$
X=\{WA,NT,Q,NSW,V,SA,T\},
\qquad D_i=\{\text{red},\text{green},\text{blue}\}.
$$

The constraints are:

$$
\begin{aligned}
SA&\neq WA, & SA&\neq NT, & SA&\neq Q,\\
SA&\neq NSW, & SA&\neq V, & WA&\neq NT,\\
NT&\neq Q, & Q&\neq NSW, & NSW&\neq V.
\end{aligned}
$$

For a binary CSP, the ***CONSTRAINT GRAPH*** has variables as nodes and binary constraints as edges. Tasmania $T$ has no neighbours and can be colored independently.

\bigskip
> ***Job Scheduling***

Variables represent task start times. Constraints enforce precedence and completion deadlines.

If installing the front axle takes $10$ minutes, the right front wheel can only be installed afterwards:

$$
\mathrm{AxleF}+10\leq\mathrm{WheelRF}.
$$

\bigskip
> ***Cryptarithmetic***

In the puzzle $TWO+TWO=FOUR$, letters represent digits and $C_1,C_2,C_3$ represent carries:

$$
\begin{aligned}
2O&=R+10C_1,\\
2W+C_1&=U+10C_2,\\
2T+C_2&=O+10C_3,\\
C_3&=F.
\end{aligned}
$$

Letter domains are $\{0,\ldots,9\}$, carry domains are $\{0,1\}$, and leading letters $T,F$ cannot be zero. An $\mathrm{AllDiff}(T,W,O,F,U,R)$ constraint requires different letters to have different digits.

In the slide diagram, circles represent variables and squares represent constraints. Each square connects all variables in its scope, including constraints involving more than two variables.

## Types of CSP

### Domains

| **Type** | **Example** |
| - | - |
| Finite | $D_i=\{\text{red},\text{green},\text{blue}\}$ |
| Infinite discrete | $D_i=\mathbb N$ or a set of strings |
| Continuous | $D_i=\mathbb R$ |

Finite domains do not guarantee an easy problem: propositional satisfiability can be hard. Continuous domains do not guarantee a hard problem: linear programming admits polynomial-time algorithms.

### Constraint Arity

| **Type** | **Variables Involved** | **Example** |
| - | - | - |
| Unary | one | $SA\neq\text{green}$ |
| Binary | two | $SA\neq NSW$ |
| Ternary | three | $X+Y=Z$ |
| Global | a collection of variables | $\mathrm{AllDiff}(X_1,\ldots,X_n)$ |

For finite-domain CSPs, higher-arity constraints can be converted to unary and binary constraints using auxiliary variables. The resulting representation may be much larger.

## Local Search

Local search starts from a complete assignment that may violate constraints. It changes variable values to reduce the number of conflicts.

### Min-Conflicts

The algorithm selects a random conflicted variable and assigns it a value that minimizes its conflicts. It stores a complete assignment and changes one variable at each step.

The value selection rule is:

$$
\boxed{v\in\arg\min_{u\in D_i}\mathrm{Conflicts}(X_i,u,s)}
$$

where $\mathrm{Conflicts}(X_i,u,s)$ counts violated constraints involving $X_i$ if it takes value $u$ in assignment $s$.

\bigskip
> ***Pseudocode***

The Python pseudocode keeps the abstract operations used in the slides. `choice` randomly selects an element; `conflicted` returns variables involved in violated constraints.

```py
def min_conflicts(csp, max_steps):
    current = csp.random_assignment()
    for _ in range(max_steps):
        if csp.is_solution(current):
            return current
        var = choice(csp.conflicted(current))
        current[var] = min(csp.domains[var], key=lambda value:
                           csp.conflicts(var, value, current))
    return None
```

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Complete | No, with a fixed step limit |
| Advantages | often effective on large scheduling problems |
| Disadvantages | can wander across plateaus without solving the CSP |

Failure after the step limit does not prove that the CSP is unsatisfiable.

\bigskip
> ***Plateaus***

A plateau offers no single-variable change that reduces the number of conflicts. Possible remedies are:

- **Tabu search:** forbid returning to recently visited assignments.
- **Constraint weighting:** increase the weight of repeatedly violated constraints, making them more important in the objective.

## Constraint Propagation

Constraint propagation removes values that cannot satisfy constraints. Reducing one domain may force reductions in other domains.

Propagation can run before search and after each assignment. Stronger consistency checks can remove more possibilities, but cost more to enforce.

### Node Consistency

A variable is ***NODE-CONSISTENT*** if every value in its domain satisfies its unary constraints.

For example:

$$
D_{SA}=\{\text{red},\text{green},\text{blue}\},
\quad SA\neq\text{red}
\quad\Rightarrow\quad D_{SA}=\{\text{green},\text{blue}\}.
$$

### Arc Consistency

A directed arc $X_i\to X_j$ is ***ARC-CONSISTENT*** if every value of $X_i$ has a compatible value in $D_j$:

$$
\boxed{\forall x\in D_i\;\exists y\in D_j:\quad C_{ij}(x,y)}
$$

where $C_{ij}$ represents the binary constraint between the variables. A compatible value $y$ is a ***SUPPORT*** for $x$.

For example:

$$
D_{SA}=\{\text{red},\text{green},\text{blue}\},
\quad D_{WA}=\{\text{red}\},
\quad SA\neq WA.
$$

The value red has no support for $SA$, so it must be removed from $D_{SA}$.

Arc consistency is directional: checking $X_i\to X_j$ may remove values from $D_i$, not $D_j$. A binary CSP is arc-consistent when all directed arcs are consistent.

### AC-3

The algorithm removes unsupported values, rechecking neighbouring arcs whenever a domain shrinks. It uses a queue of directed arcs to propagate domain reductions.

\bigskip
> ***Pseudocode***

Domains are mutable sets. `allowed(x, a, y, b)` checks the binary constraints between the two variables; `arcs()` returns both directions of every edge.

```py
def ac3(csp, arcs=None):
    queue = deque(csp.arcs() if arcs is None else arcs)
    while queue:
        x, y = queue.popleft()
        if revise(csp, x, y):
            if not csp.domains[x]:
                return False
            queue.extend((z, x) for z in csp.neighbours[x] if z != y)
    return True

def revise(csp, x, y):
    unsupported = {a for a in csp.domains[x]
                   if not any(csp.allowed(x, a, y, b)
                              for b in csp.domains[y])}
    csp.domains[x] -= unsupported
    return bool(unsupported)
```

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Time | $O(cd^3)$ |
| Advantages | reduces domains before or during search |
| Disadvantages | arc consistency does not guarantee a solution |

Here $c$ is the number of binary constraints and $d$ is the maximum domain size. Each arc is reconsidered $O(d)$ times, and each revision checks up to $d^2$ value pairs.

If $D_i$ shrinks, values in neighbouring domains may lose their support. This is why AC-3 rechecks incoming arcs $X_k\to X_i$.

***Assumptions:***

- Finite, initially nonempty domains and constant-time binary constraint checks.
- `False` detects inconsistency; `True` means no inconsistency was found by arc consistency.

### Stronger Consistency

- **Path consistency:** every consistent assignment to two variables extends to any specified third variable. It can remove incompatible value pairs.
- **$k$-consistency:** every consistent assignment to $k-1$ variables extends to any specified additional variable.
- **Global constraint propagation:** reason about a whole collection of variables together.

For example, an $\mathrm{AllDiff}$ constraint is impossible if the union of its domains contains fewer values than variables.

Two-coloring a triangle is arc-consistent, but impossible: after assigning two adjacent variables different colors, neither color remains for the third. Path consistency detects this conflict.

\bigskip
> ***After Propagation***

- **Empty domain:** no solution remains for the current branch.
- **All singleton domains:** check the resulting complete assignment.
- **Multiple remaining values:** search is still needed in general.

## Backtracking Search

Backtracking builds a consistent partial assignment one variable at a time. Variable order affects efficiency, but does not change which complete assignments satisfy the constraints.

### Backtracking Algorithm

The algorithm assigns a consistent value to an unassigned variable, undoing the choice when the branch fails. It uses recursive depth-first search and inference to reduce the remaining domains.

\bigskip
> ***Pseudocode***

`consistent` checks the candidate against the current assignment. `infer` reduces domains and returns `False` on failure; domain copies restore every reduction when backtracking.

```py
def backtracking_search(csp):
    return backtrack(csp, {})

def backtrack(csp, assignment):
    if len(assignment) == len(csp.variables):
        return assignment.copy()
    var = csp.select_unassigned(assignment)
    for value in csp.order_values(var, assignment):
        if csp.consistent(var, value, assignment):
            saved = {x: values.copy() for x, values in csp.domains.items()}
            assignment[var] = value
            csp.domains[var] = {value}
            if csp.infer(var, assignment):
                result = backtrack(csp, assignment)
                if result is not None:
                    return result
            csp.domains = saved
            del assignment[var]
    return None
```

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Complete | Yes, for finite domains and exhaustive value choices |
| Advantages | combines systematic search with pruning |
| Disadvantages | exponential worst-case search |

There are up to $d^n$ complete assignments for $n$ variables with maximum domain size $d$. Heuristics and inference reduce how many are explored.

### Variable Ordering

| **Heuristic** | **Selection Rule** |
| - | - |
| Static ordering | use a fixed order |
| Random ordering | choose randomly; can be combined with restarts |
| Minimum Remaining Values (MRV) | choose the variable with the fewest legal values |
| Degree heuristic | choose the variable constraining the most unassigned neighbours |

The degree heuristic is often used to break MRV ties.

Variable ordering follows ***FAIL-FIRST***: expose an impossible branch as early as possible.

### Value Ordering

The ***LEAST CONSTRAINING VALUE (LCV)*** heuristic tries the value that removes the fewest choices from neighbouring unassigned variables.

Value ordering follows ***FAIL-LAST***: try a promising value first, since one successful value is enough.

$$
\boxed{\text{MRV: hardest variable first}\qquad
\text{LCV: least restrictive value first}}
$$

### Inference

\bigskip
> ***Forward Checking***

After assigning $X_i=v$, remove values incompatible with $v$ from each unassigned neighbour's domain. It is fast, but does not propagate conflicts between other unassigned variables.

\bigskip
> ***Maintaining Arc Consistency (MAC)***

After assigning $X_i=v$, propagate reductions through AC-3. Assuming the CSP was already arc-consistent, initialize the queue with:

$$
\boxed{\{(X_j,X_i)\mid X_j\in N(X_i)\}}
$$

The direction matters: revise neighbours against the newly restricted domain of $X_i$.

MAC can detect failures earlier than forward checking, but performs more inference.

For a triangle with two colors, assigning the first variable red leaves both neighbours with only blue. Forward checking finds no empty domain; MAC checks the constraint between the two neighbours and detects the failure.

### Advanced Techniques

- **Backjumping:** identify the variables responsible for a conflict and return directly to a relevant earlier choice.
- **Constraint learning:** record failing combinations as new constraints, called ***NOGOODS***, to avoid repeating them in other branches.

## Exploiting Problem Structure

### Connected Components

Independent connected components can be solved separately. For example, Tasmania's color is independent of the rest of Australia.

With equal domain size $d$, two independent components of $n$ variables each require exploring up to $2d^n$ assignments separately, rather than $d^{2n}$ jointly.

### Tree-Structured CSPs

A constraint graph is a ***TREE*** if it is connected and has no cycles: there is exactly one path between any two variables. A disconnected collection of trees is a ***FOREST***.

The algorithm removes unsupported parent values from the leaves towards the root, then assigns values from the root towards the leaves. It uses a rooted tree ordering to build a solution without backtracking.

***Assumptions:***

- Binary constraints and a tree-shaped constraint graph.
- Unary constraints have already been enforced.
- Variables are ordered with each parent before its children.

\bigskip
> ***Directional Arc Consistency***

Every remaining parent value must have support in each child's domain. Enforce this bottom-up by revising the **parent's domain** against the child's domain.

Once this holds, choose a root value and assign each child a value compatible with its parent. Different child subtrees have no constraints between them, so their choices can be completed independently.

Each of the $n-1$ edges is revised once, checking at most $d^2$ value pairs. This gives the $O(nd^2)$ running time.

\bigskip
> ***Pseudocode***

`tree_order` returns the parent-first order and a parent lookup table. `revise` is the same operation used by AC-3.

```py
def tree_csp_solver(csp):
    order, parent = csp.tree_order()
    for child in reversed(order[1:]):
        x = parent[child]
        revise(csp, x, child)
        if not csp.domains[x]:
            return None
    assignment = {}
    for var in order:
        values = [v for v in csp.domains[var]
                  if csp.consistent(var, v, assignment)]
        if not values:
            return None
        assignment[var] = values[0]
    return assignment
```

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Complete | Yes, under the tree assumptions |
| Time | $O(nd^2)$ |
| Advantages | solves a tree CSP without backtracking |
| Disadvantages | general constraint graphs contain cycles |

### Cutset Conditioning

The algorithm tries assignments to a small set of variables whose removal leaves a forest. It solves the remaining tree components after restricting their domains to match each cutset assignment.

The main steps are:

1. Find a ***CYCLE CUTSET*** of variables.
2. Choose a consistent assignment to the cutset.
3. Propagate its effects to the remaining domains.
4. Solve the remaining tree CSPs; try another cutset assignment on failure.

A small cutset can greatly reduce search. Finding a minimum cutset is NP-hard, so practical methods use approximations.

### Tree Decomposition

The algorithm groups variables into overlapping clusters arranged as a tree. It treats each cluster as a variable whose values are internally consistent assignments.

A valid decomposition must ensure that:

- Every original variable appears in a cluster.
- Every constraint's scope is contained in a cluster.
- Clusters containing the same variable form a connected subtree.

Neighbouring clusters must agree on shared variables. In the slide example, clusters $\{WA,NT,SA\}$ and $\{NT,SA,Q\}$ must assign the same colors to $NT$ and $SA$.

Small clusters make the resulting tree CSP easier to solve. Finding an optimal decomposition is computationally hard.

\bigskip
> ***Evaluation***

| **Method** | **Main Idea** | **Main Cost** |
| - | - | - |
| Cutset conditioning | assign selected variables to break cycles | enumerate cutset assignments |
| Tree decomposition | group variables to obtain a tree | store cluster assignments |

Tree decomposition can improve time at the cost of memory exponential in cluster size. Cutset conditioning can enumerate assignments one at a time, using linear space for fixed domain size.
