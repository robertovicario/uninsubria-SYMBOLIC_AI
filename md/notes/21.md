# Searching Problems

A searching problem can be formulated as a search for a path from an initial state to a goal state. This formulation assumes the environment is fully observable, deterministic, static, and discrete.

## Problem Formulation

A search problem is defined as:

$$
\boxed{\mathcal P=(S,s_0,G,A,T,c)}
$$

where:

- $S$ is the set of states.
- $s_0\in S$ is the initial state.
- $G\subseteq S$ is the set of goal states.
- $A(s)$ is the set of applicable actions in state $s$.
- $T(s,a)\in S$, for $a\in A(s)$, is the successor state.
- $c(s,a,s')$ is the cost of transitioning from $s$ to $s'$ via $a$.

Assuming $A$ is the global action set and $T$ is restricted to applicable state-action pairs, ***DETERMINISM*** follows from the fact that:

$$
T:S\times A\to S
$$

is a single-valued function.

\bigskip
> ***Paths***

A path is a sequence:

$$
\pi=(s_0,a_0,s_1,a_1,\ldots,a_{n-1},s_n)
$$

such that:

$$
\forall i\in\{0,\ldots,n-1\}:
\quad a_i\in A(s_i),\quad s_{i+1}=T(s_i,a_i)
$$

A path is a solution if:

$$
s_n\in G
$$

Its total cost is:

$$
\boxed{C(\pi)=\sum_{i=0}^{n-1}c(s_i,a_i,s_{i+1})}
$$

A solution $\pi^*$ is ***OPTIMAL*** if:

$$
\boxed{\pi^*\in\arg\min_{\pi\in\Pi_G}C(\pi)}
$$

where $\Pi_G$ denotes the set of all solution paths.

### Evaluation

A search algorithm $\mathcal{A}$ is evaluated according to four criteria:

- **Completeness:** whether $\mathcal{A}$ finds a solution whenever one exists.
- **Optimality:** whether $\mathcal{A}$ returns a minimum-cost solution.
- **Time Complexity:** number of nodes generated or expanded.
- **Space Complexity:** maximum number of nodes stored in memory.

We will use $b$ for the branching factor, $d$ for the depth of the shallowest solution, and $m$ for the maximum depth of the search tree.

## Uninformed Search

A search is uninformed if it uses only the problem definition, without any estimate of how close a state is to the goal.

The Python pseudocode uses the same abstract operations as the slides: `Node` creates a search node, `expand` generates its children, and `is_cycle` checks its ancestor path. Nodes store `state`, path cost `g` (initially zero), and `depth` (initially zero). `PriorityQueue` pops the node with the smallest key; `peek` reads it without removal. `None` means failure; `"cutoff"` means the depth limit was reached. Heuristics `h` take a node. For bidirectional search, `join_nodes` joins the two paths in forward order, and `terminated` checks the stopping condition for the chosen search strategy.

### Breadth-First Search (BFS)

The algorithm expands nodes in order of increasing depth, exploring the shallowest nodes first. It uses a FIFO queue to store the frontier.

If the shallowest solution is at depth $d$, the number of nodes grows as:

$$
1+b+b^2+\cdots+b^d=O(b^d)
$$

\bigskip
> ***Pseudocode***

```py
def bfs(problem):
    node = Node(problem.initial)
    if problem.is_goal(node.state):
        return node
    frontier, reached = deque([node]), {node.state}
    while frontier:
        for child in expand(problem, frontier.popleft()):
            if problem.is_goal(child.state):
                return child
            if child.state not in reached:
                reached.add(child.state)
                frontier.append(child)
    return None
```

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Complete | $\text{Yes}^{1}$ |
| Optimal | $\text{Yes}^{3}$ |
| Space | $O(b^d)$ |
| Time | $O(b^d)$ |
| Advantages | finds shallowest solution |
| Disadvantages | high memory usage |

***Assumptions:***

- (1) complete if $b$ is finite, and the state space either has a solution or is finite.
- (3) cost-optimal if action costs are identical.

### Uniform-Cost Search (UCS)

The algorithm expands nodes in order of increasing path cost, exploring the cheapest paths first. It uses a priority queue ordered by $g(n)$ to store the frontier.

It is equivalent to Dijkstra's algorithm when applied to shortest-path search with non-negative edge costs:

$$
f(n)=g(n)
$$

where $g(n)$ is the cost from the initial state to node $n$.

\bigskip
> ***Pseudocode***

```py
def best_first_search(problem, f):
    node = Node(problem.initial)
    frontier = PriorityQueue([node], key=f)
    reached = {node.state: node}
    while frontier:
        node = frontier.pop()
        if problem.is_goal(node.state):
            return node
        for child in expand(problem, node):
            s = child.state
            if s not in reached or child.g < reached[s].g:
                reached[s] = child
                frontier.add(child)
    return None

def ucs(problem):
    return best_first_search(problem, lambda n: n.g)
```

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Complete | $\text{Yes}^{1,2}$ |
| Optimal | $\text{Yes}$ |
| Space | $O(b^{1+\lfloor C^*/\varepsilon\rfloor})$ |
| Time | $O(b^{1+\lfloor C^*/\varepsilon\rfloor})$ |
| Advantages | finds the least-cost solution |
| Disadvantages | high time and memory usage |

***Assumptions:***

- (1) complete if $b$ is finite, and the state space either has a solution or is finite.
- (2) complete if all action costs are $\geq \varepsilon > 0$.

### Depth-First Search (DFS)

The algorithm expands nodes in order of decreasing depth, following a branch as far as possible before backtracking. It uses a LIFO stack to store the frontier.

If $b$ is the branching factor and $m$ is the maximum depth, the number of nodes explored can grow exponentially:

$$
1+b+b^2+\cdots+b^m=O(b^m)
$$

\bigskip
> ***Pseudocode***

```py
def dfs(problem):
    return dls(problem, float("inf"))
```

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Complete | $\text{No}$ |
| Optimal | $\text{No}$ |
| Time | $O(b^m)$ |
| Space | $O(bm)$ |
| Advantages | low memory usage |
| Disadvantages | can get stuck in infinite branches |

### Depth-Limited Search (DLS)

The algorithm expands nodes in order of decreasing depth, following a branch up to a fixed depth limit $\ell$ before backtracking. It uses a LIFO stack to store the frontier.

The number of nodes explored is bounded by:

$$
1+b+b^2+\cdots+b^\ell=O(b^\ell)
$$

\bigskip
> ***Pseudocode***

```py
def dls(problem, limit):
    frontier = [Node(problem.initial)]
    result = None
    while frontier:
        node = frontier.pop()
        if problem.is_goal(node.state):
            return node
        if node.depth >= limit:
            result = "cutoff"
        elif not is_cycle(node):
            frontier.extend(expand(problem, node))
    return result
```

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Complete | $\text{No}$ |
| Optimal | $\text{No}$ |
| Time | $O(b^\ell)$ |
| Space | $O(b\ell)$ |
| Advantages | avoids infinite-depth exploration |
| Disadvantages | may miss solutions beyond the limit |

### Iterative-Deepening Search (IDS)

The algorithm repeatedly explores the search tree with increasing depth limits, restarting from the initial node until a solution is found. It uses depth-limited DFS at each iteration, storing only the current path and its unexplored alternatives.

The depth limits are:

$$
\ell=0,1,2,\ldots,d
$$

Although nodes are explored multiple times, the asymptotic time complexity remains:

$$
1+b+b^2+\cdots+b^d=O(b^d)
$$

\bigskip
> ***Pseudocode***

```py
def ids(problem):
    for depth in count():
        result = dls(problem, depth)
        if result != "cutoff":
            return result
```

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Complete | $\text{Yes}^1$ |
| Optimal | $\text{Yes}^3$ |
| Time | $O(b^d)$ |
| Space | $O(bd)$ |
| Advantages | low memory usage |
| Disadvantages | repeated exploration of shallow nodes |

***Assumptions:***

- (1) complete if $b$ is finite, and the state space either has a solution or is finite.
- (3) cost-optimal if action costs are identical.

### Bidirectional Search

The algorithm searches forward from the initial state and backward from the goal, looking for a state reached by both searches. It uses a separate frontier for each direction, with a FIFO queue for each when both searches use BFS.

Each search explores approximately half the solution depth:

$$
b^{d/2}+b^{d/2}\ll b^d
$$

It is applicable when the goal state is known, backward transitions can be generated, and the intersection between the two frontiers can be detected efficiently.

\bigskip
> ***Pseudocode***

```py
def bidirectional_search(p_f, f_f, p_b, f_b):
    n_f, n_b = Node(p_f.initial), Node(p_b.initial)
    q_f = PriorityQueue([n_f], key=f_f)
    q_b = PriorityQueue([n_b], key=f_b)
    r_f, r_b = {n_f.state: n_f}, {n_b.state: n_b}
    solution = None
    if n_f.state == n_b.state:
        return n_f
    while not terminated(solution, q_f, q_b):
        if f_f(q_f.peek()) < f_b(q_b.peek()):
            solution = proceed("F", p_f, q_f, r_f, r_b, solution)
        else:
            solution = proceed("B", p_b, q_b, r_b, r_f, solution)
    return solution

def proceed(direction, problem, frontier, reached, other, solution):
    for child in expand(problem, frontier.pop()):
        s = child.state
        if s not in reached or child.g < reached[s].g:
            reached[s] = child
            frontier.add(child)
            if s in other:
                candidate = join_nodes(direction, child, other[s])
                if solution is None or candidate.g < solution.g:
                    solution = candidate
    return solution
```

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Complete | $\text{Yes}^{1,4}$
| Optimal | $\text{Yes}^{3,4}$ |
| Space | $O(b^{d/2})$ |
| Time | $O(b^{d/2})$ |
| Advantages | much faster than BFS for large $d$ |
| Disadvantages | high memory usage |

***Assumptions:***

- (1) complete if $b$ is finite, and the state space either has a solution or is finite.
- (3) cost-optimal if action costs are identical.
- (4) if both directions are breadth-first or uniform-cost.

## Informed Search

A search is informed if it uses a heuristic function:

$$
h:S\to\mathbb{R}_{\geq 0}
$$

to guide the search toward promising states, reducing unnecessary exploration.

\bigskip
> ***Admissible Heuristics***

Let $h^*(s)$ be the true minimum cost from $s$ to a goal. A heuristic is ***ADMISSIBLE*** if it never overestimates the actual cost:

$$
\boxed{\forall s\in S:\quad 0\leq h(s)\leq h^*(s)}
$$

An admissible heuristic is always optimistic, but not necessarily accurate.

### A* Search

The algorithm expands nodes in order of increasing estimated total cost, exploring the most promising paths first. It uses a priority queue ordered by $f(n)$ to store the frontier.

The estimated total cost is:

$$
f(n)=g(n)+h(n)
$$

where:

- $g(n)$ is the cost from the initial state to node $n$.
- $h(n)$ is the heuristic estimate from $n$ to a goal.
- $f(n)$ is the estimated total cost of a solution through $n$.


\bigskip
> ***Pseudocode***

```py
def a_star(problem, h):
    return best_first_search(problem, lambda n: n.g + h(n))
```

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Complete | $\text{Yes}$ |
| Optimal | $\text{Yes}^1$ |
| Advantages | heuristic-guided exploration |
| Disadvantages | high memory usage |

***Assumptions:***

- (1) optimal if $h$ is admissible.

\bigskip
> ***$\boxed{\text{PROOF (1)}}$***

Assume $h$ is admissible and A* returns a suboptimal solution of cost $C>C^*$, where $C^*$ is the optimal cost.

Before selecting that suboptimal goal, there must be a node $n$ on an optimal path still in the frontier, reached with its optimal cost $g^*(n)$.

Since A* selects the node with minimum $f$, selecting the suboptimal goal implies:

$$
C\leq f(n)
$$

However, by definition:

$$
f(n)=g^*(n)+h(n)
$$

Since $h$ is admissible:

$$
h(n)\leq h^*(n)
$$

Therefore, because $n$ lies on an optimal path:

$$
f(n)\leq g^*(n)+h^*(n)=C^*
$$

Combining the inequalities:

$$
\boxed{C\leq f(n)\leq C^*<C}
$$

This is ***IMPOSSIBLE***.

Hence A* cannot return a suboptimal solution under the stated assumptions.

$$
\boxed{C=C^*}
$$

### IDA* (Iterative-Deepening A*)

The algorithm repeatedly explores the search tree with increasing cost limits, skipping nodes whose estimated total cost exceeds the current limit. It uses depth-first search at each iteration, storing only the current path and its unexplored alternatives.

The estimated total cost is:

$$
f(n)=g(n)+h(n)
$$

If no solution is found, the cost limit increases to the smallest $f$-value that exceeded the previous limit.

\bigskip
> ***Pseudocode***

```py
def ida_star(problem, h):
    def search(node, limit):
        f = node.g + h(node)
        if f > limit:
            return None, f
        if problem.is_goal(node.state):
            return node, f
        next_limit = float("inf")
        if not is_cycle(node):
            for child in expand(problem, node):
                result, cost = search(child, limit)
                if result is not None:
                    return result, cost
                next_limit = min(next_limit, cost)
        return None, next_limit

    root = Node(problem.initial)
    limit = h(root)
    while limit < float("inf"):
        result, limit = search(root, limit)
        if result is not None:
            return result
    return None
```

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Complete | $\text{Yes}$ |
| Optimal | $\text{Yes}^1$ |
| Advantages | low memory usage |
| Disadvantages | high time usage |

***Assumptions:***

- (1) optimal if $h$ is admissible.

### Recursive Best-First Search (RBFS)

The algorithm follows the path with the lowest estimated total cost, backtracking when another path becomes more promising. It uses recursive depth-first search, remembering the best alternative cost at each level to decide when to backtrack.

\bigskip
> ***Pseudocode***

```py
def rbfs(problem, h):
    def search(node, limit):
        if problem.is_goal(node.state):
            return node, node.f
        successors = list(expand(problem, node))
        if not successors:
            return None, float("inf")
        for child in successors:
            child.f = max(child.g + h(child), node.f)
        while True:
            successors.sort(key=lambda n: n.f)
            best = successors[0]
            if best.f > limit or best.f == float("inf"):
                return None, best.f
            alternative = (successors[1].f if len(successors) > 1
                           else float("inf"))
            result, best.f = search(best, min(limit, alternative))
            if result is not None:
                return result, best.f

    root = Node(problem.initial)
    root.f = h(root)
    return search(root, float("inf"))[0]
```

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Complete | $\text{Yes}$ |
| Optimal | $\text{Yes}^1$ |
| Advantages | low memory usage |
| Disadvantages | high time usage |

***Assumptions:***

- (1) optimal if $h$ is admissible.
