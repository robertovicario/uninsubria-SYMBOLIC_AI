# Searching Problems in Complex Environments

## Local Search

A local search problem asks for a configuration that maximizes an objective function. The solution is the configuration itself, regardless of the path used to reach it.

The problem is defined by:

- $S$: the set of configurations.
- $N(s)$: the neighbours of configuration $s$.
- $V:S\to\mathbb R$: the objective function to maximize.

For example, the $n$-queens problem asks for a placement of $n$ queens on an $n\times n$ chessboard such that no queen attacks another. If $c(s)$ counts conflicts, a possible objective is:

$$
\boxed{V(s)=-c(s)}
$$

Local search usually stores only the current configuration, or a small set of configurations.

### Hill Climbing

The algorithm selects the neighbour with the highest objective value, stopping when no neighbour improves the current state. It stores only the current state and evaluates its neighbours at each step.

The update rule is:

$$
s'\in\arg\max_{u\in N(s)}V(u),
\qquad s\leftarrow s'\quad\text{if }V(s')>V(s).
$$

\bigskip
> ***Pseudocode***

Here `neighbours` generates nearby configurations, and `value` is the objective function.

```py
def hill_climbing(state, neighbours, value):
    while True:
        next_state = max(neighbours(state), key=value, default=state)
        if value(next_state) <= value(state):
            return state
        state = next_state
```

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Complete | No, in general |
| Optimal | No, in general |
| Advantages | simple; low memory usage |
| Disadvantages | can stop before reaching a global maximum |

\bigskip
> ***Local Optima***

Hill climbing can get stuck in:

- **Local maximum:** a state better than its neighbours, but worse than the global maximum.
- **Plateau:** a region where neighbouring states have the same objective value.
- **Ridge:** a region where progress requires a sequence of moves that are not individually improving.

\bigskip
> ***Variants***

- **Sideways moves:** allow moves with unchanged objective value to cross plateaus.
- **Stochastic:** randomly select an improving neighbour.
- **First-choice:** generate random neighbours until an improving one is found.
- **Random-restart:** restart from a random state when progress stops, keeping the best state found.

### Simulated Annealing

The algorithm selects a random neighbour, accepting improvements and sometimes accepting worse states. It stores only the current state and uses a decreasing temperature to control the probability of accepting worse moves.

Let:

$$
\Delta=V(s')-V(s).
$$

The acceptance probability is:

$$
\boxed{
P(\text{accept }s')=
\begin{cases}
1, & \Delta\geq 0,\\
e^{\Delta/T}, & \Delta<0.
\end{cases}}
$$

where $T>0$ is the ***TEMPERATURE***.

- **High temperature:** worse moves are more likely, allowing exploration.
- **Low temperature:** worse moves are less likely, favouring improvement.

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Advantages | can escape local maxima and plateaus |
| Disadvantages | performance depends on the cooling schedule |

### Local Beam Search

The algorithm generates the neighbours of all current states, keeping the $k$ best configurations for the next step. It stores a set of $k>1$ states and selects their successors together.

If the current set is $B_t$, the next set is:

$$
B_{t+1}=\operatorname{Top}_k\left(\bigcup_{s\in B_t}N(s)\right).
$$

where $\operatorname{Top}_k$ selects the $k$ configurations with the highest objective values.

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Advantages | shares information between search paths |
| Disadvantages | states can become too similar, reducing diversity |

Stochastic variants select successors probabilistically to preserve diversity.

### Evolutionary Algorithms

The algorithm generates new configurations by combining and randomly modifying selected configurations. It stores a population of candidates, using fitness to guide the selection of parents.

The main steps are:

1. Generate a random initial population.
2. Select parents according to their fitness.
3. Combine parents through ***CROSSOVER*** to generate children.
4. Randomly modify children through ***MUTATION***.
5. Optionally retain the best parents through ***ELITISM***.

Repeat until the stopping condition is satisfied, then return the best configuration found. The slides use lack of further fitness improvement as a stopping condition.

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Advantages | can combine useful parts of different configurations |
| Disadvantages | depends strongly on representation and crossover |

A useful crossover should preserve good contributions from both parents. For numerical configurations, averaging may be more meaningful than mixing their binary encodings.

### Continuous Search Spaces

A continuous configuration is represented as:

$$
x=(x_1,\ldots,x_n)\in\mathbb R^n.
$$

If the objective function is sufficiently smooth, optimization can use:

- **Gradient ascent/descent:** move in the direction of increasing/decreasing objective value.
- **Newton--Raphson:** use local derivative information to compute updates.

With constraints, the problem becomes ***CONSTRAINED OPTIMIZATION***. Convex problems admit efficient methods under suitable assumptions.

If the objective and constraints are linear, the problem is ***LINEAR PROGRAMMING***. Polynomial-time algorithms exist; the simplex method is widely used, but has exponential worst-case complexity.

## Search with Nondeterministic Actions

An action is nondeterministic if it can produce more than one successor state. Its possible outcomes are represented by:

$$
\boxed{\mathrm{RESULTS}(s,a)\subseteq S,
\qquad\mathrm{RESULTS}(s,a)\neq\varnothing}
$$

A solution must specify what to do after each possible outcome. This is a ***CONDITIONAL PLAN***.

For example, in the nondeterministic Vacuum World:

$$
\mathrm{RESULTS}(1,\texttt{suck})=\{5,8\}.
$$

A conditional plan from state $1$ is:

```text
[suck, if state = 5 then [right, suck] else []]
```

### AND-OR Search

The algorithm searches for an action whose possible outcomes can all be solved, building a conditional plan. It uses OR-nodes for action choices and AND-nodes for their possible outcomes.

The two node types are:

- **OR-node:** choose at least one solvable successor.
- **AND-node:** solve every successor.

\bigskip
> ***Solution***

A solution is a subtree such that:

1. It contains the root.
2. Every leaf is a goal.
3. Every OR-node includes at least one successor.
4. Every AND-node includes all successors.

If an action has outcomes $s_1,\ldots,s_k$, with plans $p_1,\ldots,p_k$, combine them as:

```text
if state = s1 then p1
else if state = s2 then p2
...
else if state = sk then pk
```

Depth-first, breadth-first and heuristic search ideas can be adapted to AND-OR trees. In the depth-first method from the slides, a state repeated on the current path causes that branch to fail.

***Assumptions:***

- This method searches for finite, acyclic conditional plans. Plans that rely on repeatedly trying an action require a different treatment of cycles.

## Search with Incomplete Observation

When the agent cannot identify its physical state, it searches over sets of possible states. Each set is a ***BELIEF STATE***:

$$
\boxed{b\subseteq S}
$$

### Search with No Observation

A sensorless agent must find an action sequence that reaches a goal regardless of the actual initial state.

The search problem is defined by:

- **States:** belief states $b\subseteq S$.
- **Initial state:** all physical states compatible with the initial information.
- **Actions:** actions available in at least one possible state.
- **Transitions:** all possible successors of the current belief state.
- **Goal:** every remaining possible state is a goal.

Assuming illegal actions leave the state unchanged:

$$
A(b)=\bigcup_{s\in b}A(s).
$$

Extend $T(s,a)=s$ to actions illegal in $s$. For deterministic physical transitions:

$$
\boxed{T(b,a)=\{T(s,a)\mid s\in b\}}
$$

The goal condition is:

$$
\boxed{b\subseteq G}
$$

For nondeterministic physical transitions, take the union of all possible outcomes instead.

\bigskip
> ***Evaluation***

- With $N$ physical states, there are up to $2^N$ belief states.
- Not every belief state is reachable or relevant.
- If a plan solves $b$, the same plan solves every $b'\subseteq b$.
- Logical representations can be more compact than explicit sets.
- Action costs may use worst-case or expected cost, depending on the problem.

An alternative is ***INCREMENTAL BELIEF-STATE SEARCH***: find a plan for one possible initial state, check it against the others, and refine the search when it fails.

### Search with Partial Observation

With partial observation, an action changes the physical state and a percept reduces uncertainty. The belief state is updated through three steps:

1. **Predict:** compute possible states after the action.
2. **Percept:** determine which observations are possible.
3. **Update:** retain only states compatible with the received observation.

Formally:

$$
\begin{aligned}
\mathrm{Predict}(b,a)&=\hat b=\{T(s,a)\mid s\in b\},\\
\mathrm{PossiblePercepts}(\hat b)&=\{\mathrm{Percept}(s)\mid s\in\hat b\},\\
\mathrm{Update}(\hat b,o)&=\{s\in\hat b\mid\mathrm{Percept}(s)=o\}.
\end{aligned}
$$

Different percepts produce different successor belief states:

$$
\boxed{\mathrm{RESULTS}(b,a)=
\{\mathrm{Update}(\hat b,o)\mid o\in\mathrm{PossiblePercepts}(\hat b)\}}
$$

where $\hat b=\mathrm{Predict}(b,a)$.

Actions are therefore nondeterministic at the belief-state level, even when physical transitions are deterministic. AND-OR search can build a plan for every possible percept.

## Online Search

An online agent alternates computation, observation and action while exploring an unknown environment. It learns transition outcomes and costs by executing actions.

***Assumptions:***

- The environment is deterministic and observable.
- $A(s)$ gives the legal actions in the current state.
- The successor $s'$ and cost $c(s,a,s')$ become known after trying $a$.
- The agent can test whether its current state is a goal.

\bigskip
> ***Competitive Ratio***

The cost of exploration is measured by:

$$
\boxed{\text{Competitive ratio}=
\frac{\text{total cost of the executed path}}{\text{cost of an optimal path}}}
$$

The executed path includes exploration and backtracking. Even with reversible actions, an unknown environment can make this ratio arbitrarily large.

If actions are irreversible, the agent may enter a ***DEAD END*** from which the goal is unreachable.

### Online Depth-First Search

The algorithm tries unexplored actions, returning to earlier states when no unexplored action remains. It stores observed transitions and the actions still to try in each visited state.

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Complete | Yes, under the assumptions below |
| Optimal | No |
| Advantages | systematically explores an unknown environment |
| Disadvantages | competitive ratio can be arbitrarily large |

***Assumptions:***

- A finite reachable state space, reversible actions and a reachable goal.

### Online Hill Climbing

The algorithm selects an action that improves its heuristic estimate of distance to the goal. It uses the current state and the heuristic to guide each move.

Unlike offline local search, the agent cannot freely restart from a random state: it must physically execute actions to move elsewhere. A local minimum can therefore block progress.

### Random Walk

The algorithm chooses a random untried action when one is available, otherwise choosing a random legal action. It uses random choices to continue exploration when no heuristic improvement is available.

\bigskip
> ***Evaluation***

| **Criterion** | **Value** |
| - | - |
| Complete | With probability $1$, under the assumptions below |
| Optimal | No |
| Advantages | simple; can escape local minima |
| Disadvantages | expected exploration cost can be exponential |

***Assumptions:***

- A finite reachable state space, reversible actions and a reachable goal.
- Every available action has a positive probability of selection.

### Learning Real-Time A* (LRTA*)

The algorithm chooses the action with the lowest estimated cost to the goal, updating its estimates as it explores. It stores observed transitions and a table $H(s)$ of estimated remaining costs.

When a state is first visited:

$$
H(s)\leftarrow h(s).
$$

After executing $a$ in $s$ and observing $s'$:

1. Record the transition $\mathrm{result}[s,a]=s'$.
2. Update the estimate of the previous state $s$.
3. Choose the next action from the current state $s'$.

The update is:

$$
\boxed{H(s)\leftarrow\min_{a\in A(s)}
\mathrm{LRTA\text{-}Cost}(s,a,\mathrm{result}[s,a])}
$$

where:

$$
\mathrm{LRTA\text{-}Cost}(s,a,u)=
\begin{cases}
h(s), & \text{if the successor }u\text{ is unknown},\\
c(s,a,u)+H(u), & \text{otherwise}.
\end{cases}
$$

The next action minimizes the same cost estimate at $s'$. Updating $H$ can make an apparent local minimum less attractive, allowing the agent to leave it.
